Settings

v3 – all item kinds, add rows, menus, drag & drop

  • Workbench (pinned, top): the global settings set outside the DPF (Field, Ensembles, Realization filter…). Read-only here; settings that depend on them show a global chip. No rails – they apply to everything.
  • Root sections: Global settings (shared settings that reach every view), On top of all views and Beneath all views (providers drawn above resp. below all view layers), Views. Each section only accepts its own kind of item. Global shared-setting rails span across the views. (Interleaving root providers between views is deliberately not supported.)
  • Sticky headers: while scrolling, the ancestor chain of the first visible row (view → group …) stays pinned at the top; click a pinned row to scroll back to it. Below it, one row per shared setting in effect for the visible rows whose own row has scrolled away – name and current value, with its rail running through the row so it connects to the rail below (click to jump, hover to highlight). Sections don't stick.
  • Provider names are generated from the type and its distinguishing settings (e.g. Surface · Depth · real. 3) and update when settings change. A custom name overrides it (✎ marker in the tree, ↺ auto in the panel to revert). One icon per provider type (▲ surface, ⌇ wells, ⬠ polygons, ▦ grid, ◌ outline, ▣ base map); views use ⧉.
  • Adding: every container and section ends with a muted + Add … row – it sits exactly where the new item will land, so the target is never ambiguous. The header + is still there on hover (handy for collapsed groups). A full Delta surface shows a disabled note instead.
  • Shared setting rows show the current value as text; editing happens in the panel (many setting components are too large for a row).
  • Group with settings (Delta surface): selectable; its own settings act like shared settings for its children → it has a rail too.
  • Only items with settings are selectable (providers, shared settings, settings-groups like Delta surface). Plain views, groups and context boundaries are structure only.
  • Rail colour is the identity of a source: shared-setting / group name, rail, origin marker, and the label of each controlled setting in the panel share it.
  • ⋯ menu: Rename, Remove, Expand/collapse all, Colour (groups), Add… (containers).
  • Drag & drop: drag anywhere on a row. Drop line between rows, outlined row = drop inside. Dragging a selected row moves the whole selection. Invalid targets (shared setting below providers, view into view, into itself) show a red line.
  • Selection: click · Ctrl-click · Shift-click · Esc. Multi-select: common settings, Mixed locked until Override for all.
